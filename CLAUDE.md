# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project state

TaintTrap is a local check of every tool call an AI agent is about to make. It answers allow, ask or block. The MVP is being implemented from `specs/001-tainttrap-mvp/` (track progress in `tasks.md`).

- `PRD.md`: the source of truth for product intent, metrics, the data and model plan, and the risks.
- `specs/001-tainttrap-mvp/`: `spec.md`, `plan.md`, `research.md` (verified external facts behind design decisions), `data-model.md`, `contracts/`, `quickstart.md`, `tasks.md`.
- `.specify/memory/constitution.md`: still the unfilled template.

```bash
uv sync --extra dev --extra data                      # dev env (Python >= 3.11; --extra data is needed by the held-out set tests; add --extra cpu for the ONNX runtime)
uv run pytest -q                            # fast set: unit, contract, golden, integration
uv run pytest -q -m "not model and not ollama"   # full set, adds the fail-open audit probes (~4 min)
uv run pytest tests/unit/test_secrets.py -k lookalike -q   # a single test

uv run ruff check src tests eval scripts && uv run ruff format src tests eval scripts
uv run mypy                                 # strict on tainttrap.core
uv run python scripts/check_hook_imports.py # hook client must import only the stdlib
./scripts/lock.sh                           # uv lock + hashed requirements*.lock
uv run python -m eval.local_agent --scenario all --runs 5 --compare   # local Ollama agent, with/without TaintTrap
uv run python -m eval.detection             # replayed attack calls + benign twins, no LLM (seconds)
```

Run the full set before committing anything that touches the daemon, the hook client or the MCP proxy; CI always runs it.

Tests isolate state through `TAINTTRAP_HOME`, `TAINTTRAP_CONFIG_DIR` and `TAINTTRAP_RUNTIME_DIR` (see `tests/conftest.py`, which also fails a test if a raw fixture secret reaches a log). `tainttrap.daemon.embedded.EmbeddedDaemon` runs a real daemon in-process for tests. `TAINTTRAP_NO_AUTOSTART=1` stops the hook client from spawning a daemon.

Secret rules in `src/tainttrap/data/secrets/rules.toml` are generated by `scripts/vendor_secret_rules.py` from gitleaks/Betterleaks; regenerate them, do not hand-edit.

## Workflow: Spec Kit (spec-driven development)

Features move through `/speckit-specify` → (`/speckit-clarify`) → `/speckit-plan` → `/speckit-tasks` → (`/speckit-analyze`) → `/speckit-implement`. The skills live in `.claude/skills/speckit-*`.

- Feature directories are `specs/NNN-short-name/`, numbered sequentially (`.specify/init-options.json`).
- `.specify/feature.json` points to the active feature directory. It is machine-local and ignored by git. Downstream commands use it instead of git branch names.
- Helper scripts are in `.specify/scripts/bash/`. For example, `check-prerequisites.sh --json [--require-tasks] [--paths-only]` resolves the paths of the current feature.
- Specs describe *what* the product does, with no stack, file formats or libraries. Technology choices from the PRD belong in `plan.md`; the spec only lists them under Assumptions.

## Intended architecture (from PRD and spec)

The core is independent of how calls are intercepted. The MCP proxy and the Claude Code `PreToolUse` hook are thin adapters that translate to and from the core. Do not put decision logic in the adapters.

The decision pipeline for each call runs in order and stops at the first final answer:

1. **Dossier**: user task + tool + risk class from the **trusted registry** + arguments + **provenance** of each argument + recent actions. It is bounded at about 2048 tokens. Long arguments are shortened, keeping the start and the end.
2. **Rules** (deterministic, milliseconds): secret patterns, allow and deny lists for domains and commands, budgets. They run before the model and can decide alone.
3. **Model**: a local fine-tuned classifier that answers in one pass: `aligned`, `risk`, `sensitive_data` and `needs_human`, each a probability except `risk`, which is a class. Until a verified Laya ONNX artifact is installed, the daemon uses `HeuristicProvider` (`core/model/heuristic.py`), which judges alignment from argument provenance only.
4. **LLM judge**: only for the unsure band. Off by default. It is the only path by which data may leave the machine.
5. **Human**: approval in the terminal. A timeout resolves to deny.

The **policy** maps these outputs to a decision. There are three modes: `observe` (the default: log only, enforce nothing), `soft` and `strict`. A failure-mode switch (fail-open by default, or fail-closed) decides what happens when the model or the judge is down.

These invariants are easy to break by accident:

- Never use tool descriptions advertised by MCP servers. Risk classes come only from the trusted registry, and tools missing from it get the `unknown` class.
- Provenance is the strongest signal. Values from tool responses are untrusted. Matching must also catch base64-encoded, URL-encoded, partial and case-changed copies of them.
- Secrets are masked in every log entry. Proxy credentials are never logged.
- Policy, registry and log files must stay out of the agent's reach. Agent calls that edit them or stop TaintTrap are blocked. The shell side of `self_protect` is text matching (a deny-list, evadable); the guarantee is the managed install (`--scope managed --disable-bypass`) with the `ConfigChange` hook.
- Load models only from safetensors, with a pinned version and a checked hash. Never use pickle. Pin all dependencies.
- No telemetry by default.
- Two failure cases are distinct: an unavailable *model* is handled by `failure_mode` inside the daemon (rules still run, decision logged); an unreachable *daemon* means no checks ran, so adapters allow only in observe mode and otherwise ask. The installer always sets `onFailure: "block"` on the PreToolUse hook (a crashed or timed-out command hook otherwise lets the call run).
- The `tainttrap-hook` client (`src/tainttrap/hookclient.py`) imports only the standard library, and `tainttrap/__init__.py` stays import-free. Both rules keep the hook's cold start low. The client returns a deny as JSON with exit code 0 and never exits with 1, because Claude Code treats exit 1 as non-blocking and would run the tool.

## Model and data rules

- Split training and test data by tool family and task template, never at random. Never use test sets for threshold tuning; calibrate on a separate validation set.
- Held-out sets are frozen in `eval/holdout.json` (`python -m eval.holdout`): every detection-benchmark case (its `model_test` subset is the hard, paraphrased and lookalike-host cases), every local-agent scenario, and the external benchmarks from the PRD. They never enter training, validation or threshold tuning, synthetic generators must not reuse their templates, and every training record names its origin (`meta.source`, `source_version`, `generator`) so `python -m eval.holdout check` can run on the whole training set. It rejects a record that repeats a held-out attack (same tool, attack target and payload), even paraphrased; `python -m eval.holdout attackers` lists the held-out attacker hosts, addresses and payloads that generators must not use.
- Check an open dataset's license for commercial use before it enters training. Datasets that fail the check are for testing only.
- Release gate: ≥ 90% of attacks blocked, ≥ 98% of normal actions allowed without a prompt (measured on at least 750 real traces), and ≤ 10% of decisions sent to the judge. Report each benchmark separately, with confidence intervals.
